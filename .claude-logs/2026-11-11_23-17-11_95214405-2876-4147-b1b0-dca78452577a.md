I opened [Khaan25/session-coach#93](https://github.com/Khaan25/session-coach/pull/93) against `main` with 5 fixes from the audit. One is a production bug: the session page loaded blank. Local checks and `pnpm build` pass, but CI was still running when I stopped.

**How I tested:** I loaded every public and signed-in route at 320, 375, 768, 1024 and 1440px, with touch emulation at 768 and below. Then I ran a phone pass on a production build over a throttled 3G connection with the CPU slowed 4x. Everything ran against the local Supabase stack.

**Fixes** (one commit each):

1. **Session page blank in production.** Opening `/s/<id>` directly gave a blank page for every real session. A placeholder param in `generateStaticParams` was the cause: the breadcrumb's `usePathname()` threw outside `<Suspense>`. The route now uses `instant = false`, the same as `/review/[cardId]`. This only shows on a production build, not in `pnpm dev`.
2. **Phone sidebar hydration error.** Every signed-in page at 320 and 375px logged "Hydration failed", so that part of the page re-rendered in the browser. `Sidebar` now reads `useIsMobile()` itself instead of taking it from context.
3. **Card header actions at narrow widths.** On Settings → Devices, the "Check this" badge squeezed the description into a thin column. Under a narrow header the action now sits beside the title, and the description takes the full width.
   - My first version of this broke the 1024px layout: the title overlapped the description. I fixed it and checked that no header action overlaps its title or description at any of the 5 widths.
4. **Setup "Connected devices" header.** It had the same squeeze from "Use a token instead". It now stacks below `sm`.
5. **`/how-it-works` steps blank on 3G.** The scroll animation started every block hidden, so the steps stayed empty until JavaScript loaded. Time until the main content shows went from 6.1 s to 2.0 s. Blocks above the fold now render visible, and blocks further down still animate in on scroll.

**Checked and fine:** no sideways scrolling at any width, no inputs small enough to make iOS zoom in, no layout shift on any route over 3G. The sidebar button also opens the menu when tapped right after the page first appears.

**Not fixed, on purpose:**
- On Setup at 320 and 375px, the "Gemini" tab is cut off. The tabs scroll sideways by design, and the cut-off tab hints at that.
- Once stacked, the "Use a token instead" button sits 12px in from the heading. Shifting it would misalign any bordered button passed in its place.
- The footer links are 19px tall, under the 24px minimum tap size. I left them alone.

`Reveal` is now CSS only, with no JavaScript, and I pushed it to [Khaan25/session-coach#93](https://github.com/Khaan25/session-coach/pull/93) as `f6ec329`.

**How it works now:**
- [reveal.tsx](apps/web/src/components/marketing/reveal.tsx) is a plain server `div` with a `reveal` class. It no longer uses motion or `"use client"`.
- The new `reveal` utility in [theme.css](apps/web/src/styles/theme.css) runs the existing `enter` keyframes on `animation-timeline: view()`, over `entry 0% entry 50%`.
- It is wrapped in `@supports (animation-timeline: view())` and `prefers-reduced-motion: no-preference`. Browsers without scroll timelines, and people who turn on reduced motion, see the block shown with no animation.
- I removed `--dur-reveal` from `tokens.css` because nothing uses it any more.

**Tested on a production build at 375px with touch:**

| Check | Result |
|---|---|
| JavaScript on vs off | Same results: the first step is fully shown at load, and each step fades in as it scrolls into view |
| 3G + 4x slower CPU, `/how-it-works` | LCP 1.96 s; the screenshot at 3 s shows step 1 in full |
| Format, typecheck, lint, check:secrets, tests, build | All pass |

The new screenshots (3G at 3 s, and JavaScript off after scrolling) are attached and saved in `audit-screenshots/`. I also updated this fix's lines in the PR description.

**What changed in feel:**
- The reveal now follows the scroll position instead of playing for a fixed 0.7 s. Scrolling back up runs the fade in reverse.
- Firefox shows the blocks with no animation, because it doesn't support scroll timelines yet. Safari 26 and Chrome animate them.
- I didn't check it in Safari myself.
