The main reason is reduced motion. A raw class like `duration-150` is a fixed number, so it ignores the reduced-motion override in `apps/web/src/styles/tokens.css`. The `--dur-*` tokens are what that override switches off:

```css
@media (prefers-reduced-motion: reduce) {
  --dur-base: 0ms;
  --dur-slow: 0ms;
  ...
}
:root [data-force-reduced-motion] { --dur-base: 0ms; ... }
```

So `duration-(--dur-base)` drops to 0 ms for someone who asked for reduced motion, and also inside any `[data-force-reduced-motion]` wrapper. `duration-150` keeps animating for them.

Two smaller reasons:
- **One scale.** The token comments already say which surface uses which value: tooltips, menus and popovers enter on `--dur-base` (160 ms) and leave on the shorter `--dur-fast` (120 ms); dialogs and sheets use `--dur-slow` (180 ms). The ui folder had drifted to 100, 150, 200 and 250, which aren't on that scale. Now changing a token retunes every component at once.
- **The new AGENTS.md rule.** It says ui components animate with `duration-(--dur-*)` and never a raw `duration-<n>`, so new code follows the same pattern.

This was a small timing change, not a pure rename:
- The tooltip enter went from 150 to 160 ms, and its exit from 100 to 120 ms.
- Elsewhere, 200 and 250 ms became 180 ms.
- `--dur-fast` is not zeroed under reduced motion, so exits like the tooltip's still play there.

The pixel diff couldn't catch this, because screenshots are still frames. I left `drawer.tsx` (450/300 ms) and `progress.tsx` (300 ms) raw, since nothing on the scale fit them.

If you'd rather keep the exact old timings, I can revert the ui files to their raw values and keep only reduced-motion handling.
