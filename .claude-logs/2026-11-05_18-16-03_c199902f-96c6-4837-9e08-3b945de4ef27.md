## 1. `~/eval-cards.mts`

It's a throwaway script outside the repo that compares extraction quality before and after a code change.

- **What it does:** For each log, it redacts with the CLI's `prepareLog`, then runs `parseSession`, `trimTimeline`, `extractCards` and `checkEvidence`, the same order as `processSession`. It records:
  - event counts, and whether the first prompt survived trimming
  - cards returned versus cards kept
  - quote-check outcomes (`ok`, `id_missing`, `too_short`, `not_in_event`, `wrong_kind`)
  - failures and 429s
  - per-card flags for backticks, code identifiers or file names, word counts, and "why" or "what does … check" questions
  
  Each card also gets a manual checklist: real decision, readable on a phone, worth asking.
- **Input:** `<label> <log1.jsonl> <log2.jsonl> ...`. The label is `old` or `new` and only names the output file. Run it from the repo root with `node --env-file=apps/web/.env.local --experimental-strip-types ...`. It takes the code from the current directory, so you switch branches between runs.
- **Real model:** Yes. It uses the repo's real `callModel` and so needs the model keys in `.env.local`. It wraps `fetch` to count 429s and sleeps 65 s between logs to avoid rate limits.
- **Output:**
  - The terminal gets counts only, with no log text.
  - A markdown report goes to `~/eval-out/<date>-<time>-<N>logs-<label>.md`. It is rewritten after each log, so a crash keeps what finished.
  - Any `failed_generation` text from an API error goes to `~/eval-out/failed-<HHMMSS>-<n>.txt`. Only its length is printed.
  
  The report contains the full card text.

## 2. `apps/web/scripts/run-extract.ts`

It's a repo script for checking extraction on one log by hand.

- **What it does:** It runs `parseSession`, `extractCards` and `checkEvidence`, then prints:
  - the title
  - each kept card with its why, evidence quotes (✓/✗), files, question and answer
  - dropped drafts with the reason their quotes failed
  - a summary of extracted, kept and dropped cards and verified quotes
  
  Unlike the eval script, it doesn't redact or trim the timeline.
- **Input:** One session log path. Run it with `pnpm --filter web extract:session <session-log.jsonl>`, which loads `.env.local` itself.
- **Real model:** Yes, through the real `callModel`.
- **Output:** Stdout only. It writes no files, and it prints card text and quotes in full.

`alias-hooks.mjs` and `register-alias.mjs` are not evals. They are the Node resolve hook that maps `@/x` to `src/x.ts` so `call-model.ts` loads outside Next, and `run-extract.ts` uses them.
