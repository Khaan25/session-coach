## 1. `trimTimeline` slices before expanding

`[...event.text]` is now `[...event.text.slice(0, MAX_EVENT_CHARS * 2 + 1)]`, with a comment saying why. At most 3,001 UTF-16 units get expanded per event, and that always yields at least 1,500 code points. A cut that lands inside a pair leaves one lone surrogate as the 3,001st item, and the existing `slice(0, MAX_EVENT_CHARS)` drops it. The new test covers both of your cases:
- **5,000,000 "a":** the text is exactly `MAX_EVENT_CHARS` long.
- **"😀" × 5,000:** it is exactly 1,500 code points, equal to `"😀".repeat(1500)`, and the last code point is a whole 😀.

The comment line is long (about 140 characters). `pnpm format` left it as is, and the checks pass.
